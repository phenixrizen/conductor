# Verification criterion delivery

1. Add bounded versioned content and optional exact command references. Preserve
   legacy serialization and immutable digests. Domain and old-wire fixtures verify
   parsing bounds, duplicate rejection and omitted-extension compatibility.
2. Validate exact criterion content under package/source admission locks and the
   existing approval/revocation boundaries. Live PostgreSQL covers unknown, stale,
   foreign and out-of-task references; receipt substitution; retained historical
   descriptions; and related-repository revocation.
3. Carry original links through isolated verification and publication admission.
   Actual Docker and cross-repository Temporal tests exercise the rebuilt worker
   image, separate check containers and retained receipt recovery.
4. Derive per-criterion support in the artifact read envelope without rewriting
   stored results. Domain/execution tests cover missing, failed, unexecuted,
   truncated and substituted evidence and multiple checks for one criterion.
5. Expose exact links in MCP proposals, shared clients and browser/CLI/TUI review.
   Signed MCP/Chromium/PostgreSQL acceptance covers proposal round trips, exact
   approval, criterion rendering, escaped descriptions and substituted-revision
   rejection, invented checks and contradictory evidence. Go normal/race/vet,
   web/contracts/docs and relevant native checks pass.

The release branch retains the tested image IDs and exact verification results in
the [runbook](../../docs/operations/verification-criteria.md). No live inference,
provider publication, merge or deployment is performed for this feature.
