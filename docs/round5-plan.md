## How to work this plan

This plan builds Round 5 of `docs/features.md` on the branch `round2-crews-events`,
from HEAD `3e1e6eb` (round 4 complete). It was written and approved on 2026-10-03;
D0 (the design branch `design/crews-graph`, commit `11d3dda`) was done the same day.

- Read `AGENTS.md` first. Its rules hold for every task.
- Do the tasks in the order of "Order and estimates of touch" at the end. A task
  is tests first (seen failing), then the code, then the task's checks, then a

## Context

Round 4 landed on `round2-crews-events` (2c9c220 → 3e1e6eb). Running it exposed what comes next, in the owner's words:

1. **Sharing.** A copied link must be openable from outside the owner's network with no `publicUrl`, no tunnel, no proxy: "that is what the STUN server gives us". Verified today: STUN/ICE only connect the *terminal data channel* of a `conductor host` session once a browser has loaded the join page and exchanged the SDP offer through the server. Nothing makes the server's HTTP page reachable. What does: automatic router port mapping (UPnP IGD, NAT-PMP, PCP) plus the STUN-discovered public address, and a real certificate for that address through `go-acme/lego`. Let's Encrypt made 6-day and IP-address certificates generally available on 2026-01-15 (`shortlived` profile, `tls-alpn-01`/`http-01` only); lego supports IP identifiers and ACME profiles. So the no-domain path is real: STUN address → mapped 443 → lego-issued IP certificate → `https://203.0.113.5/join/<token>`.
2. **Serious GitHub Actions tests**, with test accounts for the agents where plausible.
3. **Install checks.** `goose` on this machine's PATH is the Go migrations tool, not Block's Goose; the catalog only resolves the program name. Each built-in needs an identity and version probe.
4. **Every by-hand item of "Open verification (round 4)" as an automated test** (items 1–7), and item 8 decided: Resume for a member of a stopped run must work two ways.
5. **An Electron desktop app** for macOS, Linux (deb and rpm) and Windows, where Windows requires WSL2 and runs the Linux server inside it.
6. **The skill, a crew graph and charts** (added mid-planning): an agent started in a Conductor session should be able to form a crew that includes itself and open the UI, through the skill; the skill should reach every agent rather than four; the Crews page gets a DAG view (Vue Flow) and charts (Nuxt Charts) where numbers mean something; the UI design of the graph and charts is handed to Claude Design through a prompt and a pushed branch (Phase D, with D0 as the first action after approval).

**Decisions taken with the owner (2026-10-03):**
- Reach is **auto everywhere** (`conductor serve` and the desktop app): the router port is mapped by default and only the **TLS listener is ever mapped**; plain http never leaves the LAN. `reach.mode: off` and a Settings switch turn it off.
- **No public link until TLS is ready**: while no certificate exists, links keep the request/LAN address and the Share dialog says why. Plain http is never advertised publicly. A domain through lego's `dns-01` providers or `http-01` is the configured alternative to the IP path.
- **Stopped runs**: both behaviours. Resume on one ended member of a stopped run reopens the run in place; a "Resume run" action creates a new run of the crew with every member's conversation resumed in its kept worktree.
- **Order**: Phase A sharing + TLS → Phase B tests, identity probe, CI, stopped-run resume → Phase C desktop (macOS/Linux, then Windows via WSL2).
- TLS is lego ACME only: no self-signed certificates, no fingerprint pinning, no autocert.

What exists and is reused (verified in the tree): `internal/api/links.go` `publicBase(r)` (request-address fallback from 3e1e6eb); `config.PublicURLIsLocal`; the hosted-session signaling in `internal/signal` and `internal/hostagent` (one session per `conductor host` process, browser creates offer and data channel, relay fallback, ICE servers from `config.ICEServers`, pion/stun and pion/turn already in the module graph); `internal/api/lookup.go` `lookupCache` (the shape for a probe cache); the e2e harness `web/e2e/` (stub, `server.ts`, `fixtures.ts`, `examples.spec.ts`, `live.spec.ts`); `internal/crew` `ResumeMember`, `Stop` (waits `starts` and `deliveries`, so a completed stop leaves no run goroutine); the earlier desktop sketch `docs/superpowers/plans/2026-10-01-desktop-electron.md` (read for its hardening rules only; do not use any superpowers tooling).

Rules that hold throughout (AGENTS.md): argv never shell strings; new Go dependencies need a reason in the PR; tokens compared with `share.Equal`; protocol changes touch `internal/proto`, `web/app/utils/protocol.ts`, `docs/protocol.md` together; every route and limit gets a test; `internal/web/dist` is never committed. Each task: tests first, the task's checks, a review against its "Done when", one commit. Every claim about a vendor CLI, library API or platform marked **verify** is checked against the real thing during the task, and the text changed if it differs.
