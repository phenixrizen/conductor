# Crews Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Saved crews of named agents with role prompts, per-member git worktrees and start conditions, launched in one click or with `conductor up <crew>`, and a crew running view with tiles, a hook-event feed, mid-run additions, a broadcast bar, share and stop-all (mockup 2a and 2b).

**Architecture:** A crew is a document in `dataDir/crews.json`. Launching one creates a run (`internal/crew` package): each member becomes an ordinary server session (so every existing feature applies) tagged with `Info.Crew{RunID, CrewID, Member}`; the run engine creates worktrees with `git` argv, waits for each session to be ready, types the role prompt, starts members whose condition is "after X idle" when X first reports `done`, delivers `handoff` events into the target member's terminal, and stops all on request. Runs are in memory like sessions; crews persist. The crew running view is the wall's tiles and queue filtered to one run, plus a broadcast bar that goes through one admin route so it is atomic across members.

**Tech Stack:** Go stdlib (`os/exec` for `git` with argv only), Nuxt UI. No new dependencies.

**Spec:** `docs/features.md` § "Round 2" (Decisions → Crews) and mockup screens 2a, 2b. Depends on Plan A (data dir, store) and Plan B (events: `handoff` entries, `OnActivity`, `POST /api/sessions/{id}/events`).

## Global Constraints

- Every crew session is a normal `session.Local` created through the same path as `POST /api/sessions` (`resolveCwd`, catalog lookup, env building, adapter injection). No second launch path.
- `git` runs as argv (`git -C <cwd> worktree add -b <branch> <path> HEAD`); branch and member names are validated `^[a-z0-9][a-z0-9._-]{0,39}$`; worktree paths live under `<cwd>/.conductor/worktrees/<run>/<member>` so they pass `resolveCwd`. Worktrees are never deleted automatically.
- Limits: ≤ 50 crews, ≤ 12 members per crew, prompt ≤ 4000 runes, goal ≤ 2000, broadcast text ≤ 4096 bytes, handoff queue ≤ 10 per member.
- Typed prompts and broadcasts are recorded as `input` activity entries with `ByName` "crew" (prompts) or the admin's display name (broadcast); they clear `needs_input` like any input and are skipped for members currently in `needs_input` (broadcast) as the mockup says.
- `$GOAL` in a role prompt is replaced by the crew goal; the environment of every member carries `CONDUCTOR_CREW`, `CONDUCTOR_RUN`, `CONDUCTOR_MEMBER`, `GOAL`.

## Review Focus

1. **The working directory is not a git repository but isolation is "worktree".** Expected: launch fails before any session starts with `not_a_repo`, and nothing is half-created. Pinned in Task 2.
2. **A member's process exits before its prompt is typed.** Expected: the prompt is dropped, the member shows exited, the run continues. Pinned in Task 2 (readiness test with an early exit).
3. **Two handoffs arrive while the target is waiting on a permission prompt.** Expected: both queue (bounded at 10), delivered in order once the target is not `needs_input`, each as its own line. Pinned in Task 3.
4. **Broadcast to a member that just went `needs_input`.** Expected: skipped and named in the response; never types into a prompt. Pinned in Task 4.
5. **The server restarts mid-run.** Expected: sessions are gone (as today); the crew document remains; the run is listed as ended with reason `server_restart` is not possible, so runs simply disappear and the crew view says "no run in progress". Documented, not engineered. Pinned in Task 5 (UI empty state).

**Files:**

**Interfaces:**
```go
package crew
type Launcher interface { // implemented by the API server
	Launch(ctx context.Context, agentID, name, cwd string, args []string, env map[string]string, ref session.CrewRef) (*session.Local, error)
}
type MemberState struct { Name, SessionID, Branch, Worktree string; Status string /* pending | starting | running | ended */; Started, Ended *time.Time; Err string }
type Run struct { ID, CrewID, Name, Goal, Cwd string; Isolation string; StartedAt time.Time; StoppedAt *time.Time; Members []MemberState; Log []session.ActivityEntry /* run-level: launched, member started, handoff delivered… ≤ 200 */ }
type Engine struct{ /* launcher, registry lookup, runs map, mu */ }
func NewEngine(l Launcher, lookup func(sessionID string) (*session.Local, bool)) *Engine
func (e *Engine) Launch(ctx context.Context, c Crew) (*Run, error)    // validates repo when worktree; creates worktrees; starts "immediately" members; returns once all are started or one failed (then stops the started ones)
func (e *Engine) Get(runID string) (Run, bool); List() []Run
func (e *Engine) StartMember(ctx context.Context, runID, member string) error // manual start / add mid-run
func (e *Engine) AddMember(ctx context.Context, runID string, m Member) error
func (e *Engine) Stop(ctx context.Context, runID string) error
func (e *Engine) OnActivity(sessionID string, entry session.ActivityEntry) // wire to the server's activity fan-out: start-conditions and handoffs (Task 3)
// readiness: Ready when attention is needs_input/done, or ≥ 1 s of output silence after the first output and ≥ 2 s since start; cap 60 s; poll every 250 ms
func awaitReady(ctx context.Context, l *session.Local) error
// worktree.go
func AddWorktree(ctx context.Context, repo, path, branch string) error  // git -C repo worktree add -b branch path HEAD; ErrNotRepo when repo has no .git
func DiffStat(ctx context.Context, worktree, base string) (added, removed int, err error) // git -C worktree diff --shortstat base...HEAD, cached 10 s by the engine
```
Env for members: `CONDUCTOR_CREW=<crewID>`, `CONDUCTOR_RUN=<runID>`, `CONDUCTOR_MEMBER=<name>`, `GOAL=<goal>` (added to the injected map so they pass `BuildEnv`).
