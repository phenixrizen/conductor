## Wiring proposal

1. **Data.** `catalog.Agent` gains `Yolo *Yolo` (`json:"yolo,omitempty"`): `{Args []string, Env map[string]string, Note string}`. Built-ins in `defaults.go` carry the recipes above (claude `--dangerously-skip-permissions`; codex `--dangerously-bypass-approvals-and-sandbox`; agy `--dangerously-skip-permissions`; copilot `--yolo` + env `COPILOT_ALLOW_ALL=true`; cursor `--yolo --trust`; opencode `--auto`; omp `--yolo`; aider `--yes-always`; goose env `GOOSE_MODE=auto`; dsh env `DSH_PERMISSION_MODE=danger-full-access`; pi `--approve`; amp `--dangerously-allow-all` pending a check; shell none). `validate` bounds it like `Command` and `Env` (NUL, 32 elements, 4096 bytes, env name rules); `Redacted` masks `Yolo.Env`; saved agents edit it in the add-agent form (an argv input and env rows, "Yolo recipe"). Operator data, not user input, so it applies even when `allowArgs` is false.
2. **Switch.** `config.Yolo bool` (`yolo`, `CONDUCTOR_YOLO=1|true`, `serve --yolo`), default off, startup `slog.Warn` when on. Per launch: `POST /api/sessions` takes `yolo?: bool` (tri-state, nil = server default); crew `Crew.Yolo *bool` and `Member.Yolo *bool` (member over crew over config); `Launcher.Launch` carries the resolved value. `conductor host --yolo` appends the built-in recipe of `--agent` (a hosted session also needs `yolo` in the `register` message: the three-place protocol rule).
3. **Launch.** One place, `createLocalSession`: argv = `Command + req.Args + yolo.Args + adapter extra`; env = adapter < `agent.Env` < `yolo.Env` < `req.Env`. Only Claude needs an adapter: add `Adapter.YoloInject` (independent of the signal kind) that swaps the `--settings` file for `claude-yolo.json` / `claude-tools-yolo.json` (hooks plus `skipDangerousModePermissionPrompt:true`), or `claude-yolo-only.json` when the signal is not hook. Written as assets at startup like the others.
4. **Trust, separate and opt-in** (`yoloTrust`, default off, because it edits a vendor config the way `hooks install` does): `Adapter.Trust(home, dir)` for claude (`~/.claude.json`, which running instances rewrite constantly: re-read, atomic rename), codex (`config.toml` block), agy (per worktree, pruned on teardown), copilot (`trustedFolders`). Target is the launch cwd after `resolveCwd` (repo root, not each worktree, for claude and codex). cursor, pi and copilot need only the arg or env in the recipe. Until built, the Launch dialog should warn that a first run in an untrusted repo stops at a dialog the run engine types into.
5. **UI.** Launch dialog: a switch showing the effective value (server default or override), the argv preview already built in `LaunchSessionModal.vue` extended with the recipe, a warning when the agent has no recipe. Crew editor: crew switch plus a per-member inherit/on/off with the effective value. Badge: `session.Info.yolo` (set only when a recipe was applied) shown as a warning-colored badge in tile, sidebar and inspector; not the junction mark.
6. **AGENTS.md rules.** Argv arrays only, no shell strings (recipes are `[]string`); catalog entries keep `allowArgs`; add-agent form updated; `resolveCwd` for the trust target; `DisallowUnknownFields` means every new request field must be declared; tests in `api_test.go` (launch argv/env, per-launch override), catalog, crew and config tests; client call in `useSessions.ts`; `docs/protocol.md` rows for `POST /api/sessions`, `Info`, crews and (hosted) `register`; `docs/features.md` for `CONDUCTOR_YOLO`.
7. **Verify before shipping:** amp flag in the rebuilt CLI; opencode TUI `--auto`; cursor `--yolo --trust` together; agy exact-path trust on 1.2.13; copilot 1.0.59 `trustedFolders`; run Claude as non-root.
